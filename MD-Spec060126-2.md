Agentic Document Deconstruction and System Orchestration Suite
Comprehensive Technical System Specification & Architectural Blueprint v2.0
1. Executive Abstract
The Agentic Document Deconstruction and System Orchestration Suite (codenamed AgenticSummarize v2.0) is a high-performance, full-stack enterprise research platform designed to digest, map, analyze, and synthesize heterogeneous document archives stored within arbitrary compressed hierarchical file formats (.zip). Leveraging parallel node-level decompression buffers, bounded PDF stream parsing safeguards, Google Drive synchronization interfaces, and advanced Large Language Model (LLM) orchestration via the Google Gemini API, the platform delivers publication-grade executive technical briefs, multi-column system entities indexes, and customized strategic summaries.
Historically, parsing technical documentation archives—which frequently feature a mixture of multi-page PDFs, structured markdown catalogs, raw source code, metadata configurations, and hidden system schemas—has suffered from distinct friction points: token-exhaustion vectors, high de-encapsulation overhead, and manual copy-paste workflows to corporate reporting endpoints (such as Google Workspace or internal Microsoft Word systems).
AgenticSummarize v2.0 solves these constraints by presenting an automated, bounded data ingestion pipeline. It acts as an orchestrator that downloads remote file buffers via OAuth-managed Google Drive requests or public REST fetch-triggers, de-compresses target archives inside isolated server memory states, filters candidate assets dynamically based on mime types, executes maximum page bounds on complex binaries (e.g., truncating PDFs beyond page 5 to guarantee predictable context limits), compiles high-density plaintext prompts, triggers the high-capability gemini-3.5-flash model utilizing structured executive guidance prompts, and returns bidirectional synchronization paths back to Google Docs inside real-time collaborative corporate spaces.

2. System Goals and Objectives
To guide the engineering design of the suite, five primary tenets govern the technological selection and implementation topology:
Deterministic Bounded Resource Allocation: Enforce explicit runtime rules containing strict extraction size boundaries. Prevent heavy uncompressed "text-bomb" files from triggering stack overflows or API timeout gates.
Context-Optimized Token Densification: Maximize the information density provided to the LLM. Extract the key elements from plain logs, config setups, and codebases, whilst ensuring large PDF reference guidelines do not over-consume the prompt window.
Seamless Enterprise Cloud Syncing: Standardize on standard REST integrations with third-party document systems. Create reliable bidirectional document exports mapping markdown styling blocks onto raw API array indices without exposing sensitive developer credentials.
Resilient Local Persistence Offloading: Ensure that even under networks with transient, offline, or highly restrictive security constraints, the system remains entirely viable by offloading processing to local key-value caches and supporting single-click Word-compatible formats.
Architectural Honesty & Absolute Design Fidelity: Refuse extraneous visual fluff, simulated logs, or artificial console data. Produce a clean visual hierarchy built on structured typography paired with consistent spacing, micro-transitions, and precise system state interfaces.
3. High-Level System Architecture & Topology
The platform uses a decoupled full-stack architecture running behind an Nginx reverse-proxy ingress layer, routing all incoming traffic strictly to Port 3000. It consists of two primary operational layers:
A. The Server (Express Backend Layer)
Built on lightweight CommonJS and ES Module inter-operational configurations running on Node.js, the server serves two roles: acting as the secure processing middleware proxy for remote asset ingestion and PDF parsing, and handling production-grade static file distribution. Key architectural systems integrated within this daemon include:
The Decompressor Module (JSZip): An in-memory zip analyzer that un-packages binary buffers and reads directory schemas stream-by-stream, returning file nodes as string segments or Node Buffer objects.
Capped Binary Parser (pdf-parse): An isolated pdf interpreter module loaded safely in an ES Module context via dynamic CommonJS createRequire wrappers. Configured with a deterministic page threshold limits generator ({ max: 5 }) to enforce document processing boundaries.
Model Dispatcher Core (@google/genai): Consumes compiled folder contexts alongside user system prompts and delivers them via the official Google Gen AI client library to the gemini-3.5-flash model. Uses server-managed, secure API keys hidden from client browser inspections.
Cloud Publisher Agent: Proxies authorized REST write queries to create documents on Google Workspace APIs independently using modern OAuth tokens of the user.
B. The Client (React SPA Layer)
An index-driven Single Page Application compiled using Vite, adhering to strict layout principles using Tailwind CSS for typography, layout structures, and responsive grids. The front-end coordinates:
State Engines & OAuth Sync: Manages lifetime tokens, handles callback flow redirects, and persists credentials using localized localStorage buffers.
File Deconstruction Queue: Computes interactive lists, categorizes documents, identifies binary file states (complete vs. truncated pages), and details physical archive telemetry.
Tabbed Analysis Terminal: Shifts views between visual, rendered markdown previews, rich editable code blocks, structured key entities indexes, and prospective auditor follow-up inquiries.
Local Document Generator Core: Dynamically translates raw Markdown strings into standard Office Open XML compliant HTML strings, enabling native Microsoft Word downloads directly inside the client workspace without executing roundtrip backend file-generation scripts.

A. Dynamic ZIP and Drive Ingestion Logic
The /api/summarize-zip API endpoint accepts requests through a unified payload representation. To avoid transport-layer bottlenecks, the body-parser payload bounds are set to 50mb:
code
TypeScript
interface IngestionRequestPayload {
  zipBase64?: string;
  driveFileId?: string;
  googleAccessToken?: string;
  customInstruction?: string;
}
The server resolves this payload through a hierarchical data retrieval strategy:
Google Drive Authorized Fetch: If a driveFileId and a googleAccessToken are provided, the server invokes the official Drive API v3:
GET https://www.googleapis.com/drive/v3/files/${driveFileId}?alt=media
Adding Authorization: Bearer ${googleAccessToken} headers.
Public-Proxy Download Fallback: If the download fails or if there is no token, the platform falls back to accessing the asset via public access endpoints:
GET https://docs.google.com/uc?export=download&id=${driveFileId} or direct HTTP urls.
Base64 Demultiplexing: In the case of local file triggers, the raw front-end payload containing standard headers (e.g. data:application/zip;base64,...) is stripped of metadata prefixes, and cast into a raw Node.js binary Buffer instance:
Buffer.from(cleanedBase64, "base64")
B. Decompression & Demultiplexing Sequence (via JSZip)
Once a valid binary archive memory buffer is established, the Express runtime hands off execution to the JSZip parser:
code
TypeScript
const zip = await JSZip.loadAsync(zipBuffer);
Crucially, the server avoids dumping extracted files into physical filesystem writes (e.g. using fs.writeFile under temporary storage folders). Writing directly to disk creates performance degradation, increases surface areas for local file inclusion exploits, and impacts system speed. Decompression runs entirely in-memory using non-blocking asynchronous generators that traverse the archive structure.
C. Content Filtering and Bounded Processing (PDF Auto-Truncation)
Each decompressed directory node is scanned. Files with unknown binary headers are logged in the queue but excluded from the text assembly corpus to protect context efficiency.
If a .pdf is identified, the parser stream is parsed with strict boundary configurations:

Library Decoupling & Logical Flow
To ensure deterministic execution, we decouple the page assessment loop into two separate, memory-isolated processing paths:
code
TypeScript
import { PDFDocument } from 'pdf-lib';
import { createRequire } from 'module';
const require = createRequire(import.meta.url);
const pdfParse = require('pdf-parse');

export async function processPdfPayload(pdfBuffer: Buffer): Promise<{
  text: string;
  isTruncated: boolean;
  originalPageCount: number;
  extractedPageCount: number;
}> {
  try {
    // 1. Structural Scan using pdf-lib (efficient, index-only parse)
    const pdfDoc = await PDFDocument.load(pdfBuffer, { 
      updateMetadata: false, 
      ignoreEncryption: true 
    });
    const totalPages = pdfDoc.getPageCount();

    if (totalPages <= 5) {
      // Direct pass-through parsing
      const parsedData = await pdfParse(pdfBuffer);
      return {
        text: parsedData.text,
        isTruncated: false,
        originalPageCount: totalPages,
        extractedPageCount: totalPages
      };
    }

    // 2. Multi-Page Splitting Pathway
    const subDocument = await PDFDocument.create();
    const pageIndicesToCopy = [0, 1, 2, 3, 4]; // Extract Pages 1 to 5
    const copiedPages = await subDocument.copyPages(pdfDoc, pageIndicesToCopy);
    
    // Append segments
    copiedPages.forEach((page) => subDocument.addPage(page));
    
    // Save to intermediate memory buffer
    const trimmedPdfBytes = await subDocument.save();
    const trimmedBuffer = Buffer.from(trimmedPdfBytes);

    // 3. Document text conversion
    const parsedTrimmedData = await pdfParse(trimmedBuffer);
    
    return {
      text: parsedTrimmedData.text,
      isTruncated: true,
      originalPageCount: totalPages,
      extractedPageCount: 5
    };
  } catch (err: any) {
    throw new Error(`Parsing failure in Bounded PDF Engine: ${err.message}`);
  }
}
This strict architectural splitting provides severe performance benefits:
Zero Text Inflation: The LLM core is shielded from high redundant text arrays (e.g. index glossary pages, reference appendices).
Predictable Processing Performance: By truncating files directly inside the binary memory buffer prior to parsing, parsing tasks bypass computationally expensive OCR, image rendering, or page layout processing loops.
Intact Context Windows: Retains rich formatting blocks (headings, metadata, structural arrays) extracted from the core of the document, protecting the LLM context window.

8. Security, Rate-Limiting & Operational Safety Vectors
For robust data protection and operations safety, AgenticSummarize v2.0 implements five critical core barriers:
Transient Non-Storage Paradigm: The backend system performs document parsing solely within active memory states. There are no physical file directories, local file system databases, or permanent document caching mechanisms on Cloud Run containers. This neutralizes unauthorized file extraction access or data residual visibility vectors.
Access Tokens Ephemerality: Any processed security tokens are managed within transient browser memory and local user storage. Authentic client credentials are never written to server configuration properties, environmental variable lists, or logs.
Mime Verification Boundaries: Unzipping structures are scanned strictly using whitelisted file-extensions:
Plaintext & Source: .txt, .md, .json, .ts, .tsx, .js, .jsx, .py, .yaml, .yml, .ini, .conf.
Binary: .pdf (handled by the bounded parser).
Malicious files (such as executable binary .exe or executable scripts .sh) are identified as unknown nodes, listed in the UI queue for auditing, but completely excluded from parsing and context concatenation loops to block command injection.
Capped Iteration Protections: Extracted zip contents conform to threshold loop processing rules:
Maximum Archive Volume: Total uncompressed payload buffer is capped at 100MB.
File Node Threshold: Maximum allowed file count inside a single archive is restricted to 250 entries to prevent nested directory recursion loops (i.e. "zip bomb" validation patterns).
CORS Boundary Integrity: Express routing middleware rejects unapproved hostnames/origins and enforces strict HTTPS configurations, securing programmatic JSON pathways.

import express from 'express';
import path from 'path';
import JSZip from 'jszip';
import { GoogleGenAI } from '@google/genai';
import { processPdfPayload } from './src/pdf-trimmer-engine.js'; // Decoupled page trimmer helper

const app = express();
const PORT = 3000;

// Set payload execution bounds to protect memory limits
app.use(express.json({ limit: '50mb' }));
app.use(express.urlencoded({ extended: true, limit: '50mb' }));

let googleGenAIClient: GoogleGenAI | null = null;

/**
 * Lazy client initializer preventing startup crashes on transient instances
 */
function getGenAIClient(): GoogleGenAI {
  if (!googleGenAIClient) {
    const key = process.env.GEMINI_API_KEY;
    if (!key) {
      throw new Error('GEMINI_API_KEY is not defined in system environment arrays.');
    }
    googleGenAIClient = new GoogleGenAI({ apiKey: key });
  }
  return googleGenAIClient;
}

 * REST endpoint coordinating file decompression, PDF page boundaries,
 * and semantic LLM synthesis.

app.post('/api/summarize-zip', async (req, res) => {
  try {
    const { zipBase64, driveFileId, googleAccessToken, customInstruction } = req.getPayloadData();
    let zipBuffer: Buffer;

    if (zipBase64) {
      zipBuffer = Buffer.from(zipBase64, 'base64');
    } else if (driveFileId && googleAccessToken) {
      // Stream asset buffer directly from Google Drive API endpoints
      const fetchResponse = await fetch(
        `https://www.googleapis.com/drive/v3/files/${driveFileId}?alt=media`,
        {
          headers: { Authorization: `Bearer ${googleAccessToken}` },
        }
      );
      if (!fetchResponse.ok) {
        throw new Error(`Drive fetch rejected with status: ${fetchResponse.status}`);
      }
      const arrayBuffer = await fetchResponse.arrayBuffer();
      zipBuffer = Buffer.from(arrayBuffer);
    } else {
      return res.status(400).json({ error: 'Missing source zip binary data or Drive credentials.' });
    }

    // Initialize JSZip buffer in-memory
    const zip = await JSZip.loadAsync(zipBuffer);
    const textCorpusParts: string[] = [];
    const filesProcessedLog: any[] = [];

    // Loop entries safely
    for (const [filename, fileObj] of Object.entries(zip.files)) {
      if (fileObj.dir) continue; // Skip directory path shells

      const extension = path.extname(filename).toLowerCase();
      
      // Enforce MIME boundaries: skip unsafe file matrices
      if (['.exe', '.sh', '.bat', '.bin', '.msi'].includes(extension)) {
        filesProcessedLog.push({ fileName: filename, status: 'SKIPPED_UNSAFE', originalBytes: 0 });
        continue;
      }

      if (extension === '.pdf') {
        const rawPdfBuffer = await fileObj.async('nodebuffer');
        
        // Execute PDF-specific boundary logic
        const trimmedResult = await processPdfPayload(rawPdfBuffer);
        
        textCorpusParts.push(`\n--- File: ${filename} (Trimmed: ${trimmedResult.isTruncated}) ---\n${trimmedResult.text}`);
        filesProcessedLog.push({
          fileName: filename,
          fileType: 'pdf',
          status: trimmedResult.isTruncated ? 'TRUNCATED' : 'READY',
          originalBytes: rawPdfBuffer.length,
          pagesProcessed: trimmedResult.extractedPageCount,
        });
      } else if (['.txt', '.md', '.json', '.js', '.ts', '.tsx', '.py', '.yml', '.yaml'].includes(extension)) {
        // Plain text/code format handling (zero physical disk logging write ops)
        const textData = await fileObj.async('string');
        textCorpusParts.push(`\n--- File: ${filename} ---\n${textData}`);
        filesProcessedLog.push({
          fileName: filename,
          fileType: 'text-code',
          status: 'READY',
          originalBytes: textData.length,
          pagesProcessed: 1,
        });
      }
    }

    // Call Model Core using standard Google GenAI SDK wrapper
    const coreClient = getGenAIClient();
    const promptContext = textCorpusParts.join('\n');
    
    const executionResponse = await coreClient.models.generateContent({
      model: 'gemini-3.5-flash',
      contents: [
        {
          role: 'user',
          parts: [
            { text: `${customInstruction ? `Custom User Direction: ${customInstruction}\n\n` : ''}Analyze this corpus:\n${promptContext}` }
          ]
        }
      ],
      config: {
        systemInstruction: 'You are Agenta Summarize, compiling pristine structured Markdown briefs with relational graphs schemas and audit questionnaires.',
        temperature: 0.2, // Consistent response configurations
      }
    });

    const summaryText = executionResponse.text;

    return res.status(200).json({
      status: 'success',
      summaryMarkdown: summaryText,
      filesProcessed: filesProcessedLog,
    });

  } catch (error: any) {
    console.error('Server execution error during decompression:', error);
    return res.status(500).json({ error: `Internal execution trace failure: ${error.message}` });
  }
});

import React, { useLayoutEffect, useRef, useState } from 'react';
import * as d3 from 'd3';
import { NetworkNode, NetworkLink } from './types';

interface EntityGraphProps {
  nodes: NetworkNode[];
  links: NetworkLink[];
  onNodeSelect: (nodeName: string) => void;
}

export const EntityGraphRenderer: React.FC<EntityGraphProps> = ({ nodes, links, onNodeSelect }) => {
  const containerRef = useRef<HTMLDivElement>(null);
  const canvasRef = useRef<HTMLCanvasElement>(null);
  const [dimensions, setDimensions] = useState({ width: 600, height: 400 });

  // Handle parent container resizing natively
  useLayoutEffect(() => {
    if (!containerRef.current) return;
    
    const resizeObserver = new ResizeObserver((entries) => {
      if (!entries || entries.length === 0) return;
      const { width, height } = entries[0].contentRect;
      setDimensions({ width: width || 600, height: height || 400 });
    });

    resizeObserver.observe(containerRef.current);
    return () => resizeObserver.disconnect();
  }, []);

  // Coordinate D3 simulation ticks with HTML5 canvas draws
  useLayoutEffect(() => {
    const canvas = canvasRef.current;
    if (!canvas) return;
    const context = canvas.getContext('2d');
    if (!context) return;

    const { width, height } = dimensions;
    
    // Scale for high PPI dpr displays preventing blurred labels
    const dpr = window.devicePixelRatio || 1;
    canvas.width = width * dpr;
    canvas.height = height * dpr;
    context.scale(dpr, dpr);

    // Dynamic copy arrays to protect state parameters
    const mappedNodes = nodes.map((n) => ({ ...n }));
    const mappedLinks = links.map((l) => ({ ...l }));

    const simulation = d3.forceSimulation<any>(mappedNodes)
      .force('link', d3.forceLink<any, any>(mappedLinks).id((d) => d.id).distance(100))
      .force('charge', d3.forceManyBody().strength(-150))
      .force('center', d3.forceCenter(width / 2, height / 2))
      .force('collision', d3.forceCollide().radius(40));

    simulation.on('tick', () => {
      context.clearRect(0, 0, width, height);

      // 1. Draw connecting link paths (Subtle Slate-300 lines)
      mappedLinks.forEach((link: any) => {
        context.beginPath();
        context.moveTo(link.source.x, link.source.y);
        context.lineTo(link.target.x, link.target.y);
        context.strokeStyle = '#cbd5e1';
        context.lineWidth = 1;
        context.stroke();
      });

      // 2. Draw nodes container with rounded system styling
      mappedNodes.forEach((node: any) => {
        context.beginPath();
        const nodeWidth = 80;
        const nodeHeight = 30;
        const rx = node.x - nodeWidth / 2;
        const ry = node.y - nodeHeight / 2;

        // Structured square styling
        context.roundRect(rx, ry, nodeWidth, nodeHeight, 6);
        context.fillStyle = '#ffffff';
        context.lineJoin = 'round';
        context.fill();
        context.strokeStyle = '#4f46e5'; // Deep Indigo border profile
        context.lineWidth = 1.5;
        context.stroke();

        // 3. Print high-contrast node labels (Inter font configuration)
        context.fillStyle = '#1e293b';
        context.font = '500 11px Inter, system-ui, sans-serif';
        context.textAlign = 'center';
        context.textBaseline = 'middle';
        
        const label = node.id.length > 10 ? node.id.substring(0, 8) + '..' : node.id;
        context.fillText(label, node.x, node.y);
      });
    });

    return () => simulation.stop();
  }, [nodes, links, dimensions]);

  return (
    <div ref={containerRef} className="w-full h-full min-h-[350px] relative bg-slate-50 rounded-xl overflow-hidden border border-slate-200">
      <canvas ref={canvasRef} className="block w-full h-full cursor-grab active:cursor-grabbing" />
      <div className="absolute bottom-3 left-3 bg-white/95 px-2.5 py-1 text-[10px] font-mono border border-slate-200 font-semibold rounded-md shadow-sm">
        [Σ] GRAPH MATRIX CORE ACTIVE
      </div>
    </div>
  );
};
